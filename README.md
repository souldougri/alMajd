# مجمع المجد التعليمي العربي — نظام الإدارة

Complexe Scolaire Al-Madjd

تطبيق ويب متكامل لإدارة المدرسة: تسجيل الطلاب، الحضور، الرسوم، البطاقات، الشهادات، والإنذارات، مع حسابات مستخدمين بهوية حقيقية محفوظة على الخادم.

## المحتويات

- النظام (Desk): مسار `/app` بعد تسجيل الدخول
- الصفحة الرئيسية: متاحة للجميع
- الملصق الإعلاني: مسار `/poster`

## التشغيل

يحتاج Node.js 22 ثم:

```
npm install
npm run dev
```

ثم افتح [http://localhost:8080](http://localhost:8080).

## قاعدة البيانات

- إذا وُجد متغير بيئة `DATABASE_URL` يستخدم النظام PostgreSQL.
- وإلا يُنشئ قاعدة بيانات محلية (PGLite) في مجلد `.data/almajd` داخل المشروع.
- بيانات الحسابات والجلسات والمدرسة تُحفظ على الخادم وتبقى بعد إعادة تشغيل الخادم.

## الإعدادات (متغيرات البيئة)

انقل `.env.example` إلى `.env` وعدّل القيم، أو اضبط المتغيرات في بيئة النشر:

| المتغير                 | الوصف                                          | الافتراضي      |
| ----------------------- | ---------------------------------------------- | -------------- |
| `DATABASE_URL`          | رابط PostgreSQL اختياري؛ إن غاب يُستخدم PGLite | —              |
| `ALMAJD_ADMIN_PASSWORD` | كلمة مرور الحساب الإداري الأول عند أول تشغيل   | `AlMajd@2026!` |
| `ALMAJD_SESSION_DAYS`   | عدد أيام بقاء الجلسة                           | `30`           |

## وضعا التشغيل: الموقع العام ومنصة المدرسة

يُبنى المشروع في أحد وضعين حسب `VITE_APP_MODE`، بحيث يمكن استضافة الموقع ومنصة الدخول بشكل منفصل (مشروعان من نفس المستودع):

| الوضع              | ماذا يُعرض                                              | المسارات                                                       |
| ------------------ | ------------------------------------------------------- | -------------------------------------------------------------- |
| `site` (الافتراضي) | الموقع التسويقي: شريط وترويسة وتسويق                    | `/`، `/about`، `/programs`، `/admissions`، `/contact`، `/news` |
| `portal`           | واجهة تطبيق المدرسة: شاشة ترحيب كاملة ثم دخول ثم النظام | `/` (الترحيب)، `/login`، `/app/…`                              |

سلوك كل متغير:

| المتغير           | الوصف                                                                                                | مثال                      |
| ----------------- | ---------------------------------------------------------------------------------------------------- | ------------------------- |
| `VITE_APP_MODE`   | `site` أو `portal`؛ إذا تُرك دون قيمة فيُعتبر `site`                                                 | `site`                    |
| `VITE_PORTAL_URL` | أصل النطاق العام لمنصة الدخول؛ يوجّه إليه زر «تسجيل الدخول» في الموقع، وإلا انتقل لـ `/login` محليًا | `https://app.example.com` |
| `VITE_SITE_URL`   | أصل النطاق العام للموقع التسويقي                                                                     | `https://www.example.com` |

في وضع `portal`:

- لا تعمل واجهة الموقع التسويقي إطلاقًا؛ زر الدخول يبدأ من شاشة ترحيب كاملة (شعار المدرسة، الاسم، الشعار، زر «دخول»).
- زيارة `/about` أو غيرها من صفحات الموقع تُحوَّل إلى `/welcome`.
- بعد تسجيل الدخول ينتقل المستخدم حسب دوره (`/app/admin`، التسجيل، المحاسبة، الشؤون الدراسية، الإشراف، المعلم، الطالب، …).
- لا توجد صفحة تسجيل ذاتي.

### أوامر البناء

```
npm run build         # site (الافتراضي)
npm run build:site    # site صراحةً
npm run build:portal  # portal
```

> تطبيق سطح المكتب (Electron) يُبنى دائمًا في وضع `portal` (الشاشة الترحيبية ثم الدخول)، لأنه يعبّيء منصة المدرسة وليس الموقع التسويقي.

> ملاحظة أمنية: هذه المتغيرات تظهر في حزمة العميل، لذا ضَع فيها الروابط العامة فقط ولا تضع أي أسرار.
> لا تُرفع بيانات طلاب حقيقية؛ قاعدة البيانات تبدأ فارغة وتعتمد على حساب الإدارة الذي يُنشأ عند أول تشغيل، ويُدخل المستخدمون بياناتهم بأنفسهم بعد ذلك.

## نشر مشروعين من نفس المستودع — خطوات النشر (بالعربية)

1. ادفع المشروع إلى مستودع GitHub، ثم أنشئ مشروعين منفصلين على Vercel من نفس المستودع: الأول باسم «الموقع» (Website) والثاني باسم «المنصة» (Portal).
2. للمشروع الأول (الموقع): اختر Build Command = `npm run build:site`، وحدّد Output Directory = `.vercel/output`، وأضف `VITE_APP_MODE=site` و `VITE_PORTAL_URL=https://app.example.com`.
3. للمشروع الثاني (المنصة): اختر Build Command = `npm run build:portal`، وحدّد Output Directory = `.vercel/output`، وأضف `VITE_APP_MODE=portal` و `VITE_SITE_URL=https://www.example.com`، واربطه بقاعدة البيانات (`DATABASE_URL`) — وحده يحتاج قاعدة البيانات.
4. تقييد الوصول: المسارات `/app/…` وحدها تتطلب تسجيل الدخول، واحرص على أن يكون زر «تسجيل الدخول» في الموقع يشير إلى نطاق المنصة (بواسطة `VITE_PORTAL_URL`).
5. بعد النشر، اختبر الرابطين: الموقع يعرض الرسالة التسويقية، والمنصة تعرض شاشة الترحيب ثم صفحة الدخول، وتحقّق من الانتقال بين الموقع والمنصة بالروابط.
